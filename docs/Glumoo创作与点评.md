# Glumoo 创作、点评与数据导出

## 谁来判断成品

宠物品牌的美术指导要在手机缩略图上认出主题，也要能在原尺寸看清罐身、标签与接触阴影。电商修图人员对着正式母图核对包装身份、印字和几何。小红书内容运营对照原笔记和本账号以往作品，判断用户能从新稿里多学会什么。三个角色都可以指出具体页码和证据。人评中的好差代表该次品牌选择，不能直接解释为营养事实、销售转化或全面的模型排名。

## 一个任务怎样留下证据

1. 在首页选择风格，可将常用风格排在前面。风格 16 至 22 附带明确标为示例的 Pinterest 图片和原始链接。
2. 点击调研后，服务端从 TikHub 获取带日期的笔记并保存来源、互动数据和采集时间。有效样本达到十条时按互动门槛或相对排名入选。笔记标题为选题依据，产品事实来自用户选择的产品资产。历史比对取最近最多一百条已完成记录，按标题重叠和所选产品找出至多三条相近作品。这一步仅是候选召回。
3. 用户可以上传六张当次主参考、从审核库自选，或由视觉模型按主题和风格在库中匹配。库内检索的范围是已有图片。参考来源、选择理由和文件摘要随大纲保存。用户选择的风格始终优先于常用风格排序。
4. 每页生成先用 CPA 模型列表的第一项。明确的暂时不可用或模型不存在才继续下一项。共享认证、内容拒绝和结果未知的读取超时单独处理。成功页保存尝试顺序、返回像素、实际使用的请求模型、提示词、产品名和参考摘要。生产端接受请求的模型名并不提供关于其内部路由的独立证明。
5. 作品详情展示发布成品，新生成的直接出图页还保存模型原图。派生封面来自合格正文。拍摄质量、平台规格和预览大小分别核验。
6. 复核人员在历史详情给整套作品选好或差并填写理由。保存时核对当前作品版本，按内容哈希存下点评对应的图片。重绘过的作品可以产生新版本，同一版本修改点评会更新原记录。

## 数据和配置

- Railway 挂载卷中保存作品文件和 SQLite 点评库。对相同图像只保留一份点评快照。TikHub 密钥在服务端保存，设置接口仅返回配置状态。
- 登录后请求 `GET /api/studio/reviews.jsonl`，每行是一条已点评的作品版本。字段包括记录、版本、时间、好差、理由、实际图片及其摘要、拍摄大纲和可用的生成信息。新任务含产品、风格和调研上下文。历史任务缺失的元数据保持空值。
- 导出里的 `image_url` 是站内受保护的快照地址。下载者使用同一站点鉴权获取图片，按 `sha256` 验证。JSONL 文件本身不内嵌图片。

## 如何迭代

先取同一个正式产品、同一张主参考和同一页意图做盲评，记录包装身份、清晰度、光影、风格命中及具体失败处。再以真实任务观察每个风格的采用率、模型回退率和返工原因。人工好差与理由先用于评测，积累到覆盖多种产品和风格后，再按作品或近重复图片分组划分训练集与留出集，防止同套变体跨集合。TikHub 互动数据始终保留来源与日期，不作为品牌图片的人评标签。
